# Distribution

How `bbr` reaches users, what each channel guarantees, and how to add a release
to one.

## Channels

| Channel | Command | Platforms | Maintained by |
|---------|---------|-----------|---------------|
| Install script | `curl -fsSL …/install.sh \| bash` | Linux (x86_64/aarch64), macOS (Intel/ARM) | this repo |
| `cargo binstall` | `cargo binstall bbr` | all published targets | `[package.metadata.binstall]` in `Cargo.toml` |
| From source | `cargo install --locked --git …` | any Rust platform | this repo |
| Homebrew | `brew install themankindproject/tap/bbr` | macOS, Linux | `themankindproject/homebrew-tap` (optional) |
| Scoop | `scoop install bbr` | Windows | `themankindproject/scoop-bucket` (optional) |
| winget | `winget install themankindproject.bbr` | Windows | `microsoft/winget-pkgs` (optional) |

> **`cargo install bbr` is not this tool.** The `bbr` name on crates.io belongs
> to an unrelated crate. Always pass `--git`, or use `cargo binstall`.

## Published targets

The release matrix in `.github/workflows/release.yml` is the single source of
truth. `verify-matrix` fails the release if it drifts from
`src/commands/update.rs`.

| Target | Runner | Notes |
|--------|--------|-------|
| `x86_64-unknown-linux-musl` | ubuntu-22.04 | Static; no glibc floor. Preferred by `install.sh` and `bbr update`. |
| `aarch64-unknown-linux-musl` | ubuntu-24.04-arm | Static. |
| `x86_64-unknown-linux-gnu` | ubuntu-22.04 | glibc ≥ 2.35. Pinned so the floor does not drift with `ubuntu-latest`. |
| `aarch64-unknown-linux-gnu` | ubuntu-24.04-arm | glibc ≥ 2.35. |
| `x86_64-apple-darwin` | macos-15-intel | |
| `aarch64-apple-darwin` | macos-14 | |
| `x86_64-pc-windows-msvc` | windows-latest | |

Every leg publishes `bbr-<target>.tar.gz` (or `.zip`), a per-asset
`bbr-<target>.<ext>.sha256`, and the shell completions. The `checksums` job then
publishes a combined `checksums.txt` for all archives.

## Integrity

- **`install.sh` fails closed.** It downloads `checksums.txt`, looks up the
  exact asset, and aborts on a missing entry or a mismatched digest. There is no
  silent "verification skipped" path. `BBR_SKIP_CHECKSUM=1` is the explicit
  opt-out and prints a warning.
- **`bbr update` fails closed.** A missing `checksums.txt` or a missing entry for
  the target asset aborts the update.
- **Manifests are generated from `checksums.txt`.** `scripts/gen-packages.sh`
  reads the release's own digests, so a Homebrew/Scoop/winget manifest cannot
  advertise a hash that disagrees with the archive. A missing asset is a hard
  error, never a blank digest.

## Release checklist

1. Bump `version` in `Cargo.toml`.
2. Add a `## [<version>]` heading to `CHANGELOG.md`.
3. Commit, then tag `v<version>` and push the tag.
4. The release workflow:
   - `verify-version` — asserts tag == `Cargo.toml` == `CHANGELOG.md` heading;
   - `verify-matrix` — asserts every matrix target is known to the client;
   - `build` — compiles, smoke-tests (`--version`, `--help`), packages,
     checksums, and uploads;
   - `checksums` — publishes the combined `checksums.txt` and generates the
     package manifests;
   - `verify-install` — installs the published artifacts inside `ubuntu:22.04`
     and `alpine:3.20`, which is the gate that catches a missing asset or a
     raised glibc floor.
5. Verify `checksums.txt` lists every archive, and that `install.sh` works
   against a clean `HOME`.

## Enabling the optional registries

The generated manifests are attached to every GitHub release. To also publish
them into a package registry, create the repository and set a token — the
release workflow skips the step (and says so) when no token is present.

### Homebrew tap

1. Create `themankindproject/homebrew-tap` with a `Formula/` directory.
2. Create a fine-grained PAT with `contents: write` on that repository.
3. Add it as the `HOMEBREW_TAP_TOKEN` repository secret.

Then `brew install themankindproject/tap/bbr` works. The formula generated by
`scripts/gen-packages.sh` prefers the static musl build on Linux and selects the
right macOS archive per architecture.

### Scoop bucket

1. Create `themankindproject/scoop-bucket`.
2. Add a PAT as the `SCOOP_BUCKET_TOKEN` secret.

`bbr.json` carries `checkver`/`autoupdate` blocks, so Scoop's own tooling can
bump the version without a manual edit.

### winget

winget publishes through `microsoft/winget-pkgs`, which takes PRs rather than
writes. Submit `packages/winget/*.yaml` from a release:

```bash
wingetcreate submit --token <PAT> packages/winget
```

The manifest validates against `winget validate` for schema 1.6.0.

### Homebrew core / distro packages

Both require the project to meet the registry's own criteria (notability,
build-from-source, a stable release cadence). The formula here is written to be
submittable as-is: `bin.install "bbr"` plus generated completions.

## Adding a target

1. Add the target to the `build` matrix in `.github/workflows/release.yml`.
2. Add its triple to `target_candidates()` / `asset_candidates()` in
   `src/commands/update.rs`.
3. Add it to `scripts/gen-packages.sh` if a package manager needs it.
4. Add it to the `required` list in the `verify-matrix` job.

`verify-matrix` fails the release if steps 1 and 2 disagree.
