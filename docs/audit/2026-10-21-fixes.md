## Verified non-issues

- **Webhook update and the signing secret.** Atlassian's schema marks
  `secret_set` as "ignored during updates"; the update body intentionally
  omits `secret`, so the stored secret is not cleared. No code change.
  (`docs/audit/2026-10-21-api-spec-evidence.txt`)
- **Deployment trigger endpoint.** The path used by `bbr` is not in the
  published OpenAPI document because it is a Bitbucket UI-internal endpoint;
  Atlassian staff state that internal endpoints have no deprecation policy.
  The feature is kept, and a 404 now explains the dependency and suggests
  `bbr ci trigger`. Its request body can only be re-verified against a live
  workspace.

## Residual limitations (documented, not defects)

- `ci tail --from-offset` cannot know how many lines preceded the byte offset;
  numbering restarts at 1 and the CLI help says so.
- `ci watch` step attribution is per-step (`step` + `line_number` fields), so
  line numbers restart when a new step begins.
- Deployment trigger/history rely on a Bitbucket UI-internal endpoint with no
  public deprecation policy; the code and error path are complete, but the
  request body can only be re-verified against a live workspace.
